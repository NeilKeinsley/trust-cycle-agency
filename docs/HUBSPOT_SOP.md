# HubSpot automation package: standard operating procedure

How to sell, build, test, launch and run the "website lead to HubSpot" package. The reference build is Trust Cycle Agency (TCA); every ID, test log and decision for it is in `docs/HUBSPOT_PLAN.md`. This SOP is the reusable version: follow it for the next client and the result should look and behave the same.

Stack: a website form → n8n (automation) → HubSpot (CRM), Google Sheets (permanent record), Slack (team alerts), Calendly (bookings), Gmail (drafts). No paid add-ons are needed beyond what the client already has: it works with HubSpot's free CRM objects, Calendly's free plan and a free Slack workspace. HubSpot's own workflows (used in modules 2 and 4) need a HubSpot plan that includes workflows.

---

## 1. The package

| Module | What the client gets | Runs on |
|---|---|---|
| 1. Lead sync | Every website lead becomes a HubSpot contact and a deal in a "New business" pipeline, scored and bucketed (Hot / Qualified / Nurture). The Google Sheet stays the permanent record | n8n sub-workflow called by the lead intake |
| 2. Slack alerts + Claim | A card in #leads (Hot leads in #hot-leads) about a minute after each lead, with a **Claim** button that sets the HubSpot deal owner. Stage changes post too | HubSpot workflows → n8n → Slack |
| 3. Calendly → HubSpot | A booking made after the form becomes a HubSpot meeting on the right deal, the deal moves to "Call booked", Slack shows the time. A cancellation marks the meeting cancelled and moves the deal back | n8n polls Calendly every 5 minutes (free plan has no webhooks) |
| 4. Gmail drafts | Ready-to-send drafts in the owner's Gmail: a first reply to every new lead, a call-prep email when a call is booked, a follow-up 3 days after a proposal. Nothing is ever sent automatically | HubSpot workflows → n8n → Gmail API |
| 5. Pipeline hygiene | Weekday 09:00: stuck deals get a HubSpot task and appear in one Slack digest. Monday 08:00: every open deal is copied to a "Pipeline snapshot" sheet tab, so the pipeline has a history | n8n schedules |

Modules can be sold alone, but each one assumes module 1 (the deal is what everything hangs on).

**What to promise:** faster first response, no lead forgotten, one place to see the pipeline, an honest history in Sheets. **What not to promise:** revenue figures, "AI", "fully automatic follow-up" (the emails are drafts on purpose), or anything about deliverability (the client sends from their own Gmail).

## 2. Before you build (intake checklist)

Collect these before any work starts. Never ask for passwords or keys in chat: the client creates each key and pastes it into n8n themselves.

| Item | From the client | Notes |
|---|---|---|
| HubSpot account with workflows | Super admin invites you, or they follow your click guide | A developer test account is fine for a demo; it expires after 90 days without API calls |
| HubSpot service key | They create it under Development → Keys → Service keys | Scopes in section 4. Pasted into an n8n "HubSpot Service Key" credential |
| Pipeline stages | Their names for: New lead, Contacted, Call booked, Proposal sent, Closed won/lost | Stage **IDs** are what the automations use; record them |
| Slack workspace, two channels | #leads, #hot-leads | They install the Slack app from your manifest; bot token and signing secret go into n8n only |
| Calendly | The booking link and a personal access token | Token scopes `scheduled_events:read`, `users:read` |
| Gmail | The mailbox that should receive drafts | Google OAuth client in their Google Cloud project, scope `gmail.compose` only |
| Lead scoring rules | Budget, timeline, service points; bucket thresholds | Keep the rubric transparent and written down |
| Stale-deal limits | Days per stage before a deal counts as stuck | TCA: New lead 1, Contacted 3, Call booked 1 day after the call, Proposal sent 7 |
| Privacy page | Where lead data goes | Must list every tool above; Google won't publish the OAuth app without one |
| Consent wording | On the form | Must match what the emails say about opting out |

## 3. Build order and steps

Same loop for every module: **build as importable n8n JSON → import unpublished → test on pinned data → go live with the client's yes → one real test → clean up → document.** Keep the workflow files in the client's repo (`n8n/*.workflow.json`), generated by a script, so a rebuild is repeatable.

### Module 1: lead sync
1. Run the setup workflow (`hubspot-setup-properties`) once. It creates the property group and every custom property on contacts, deals and meetings, and is safe to re-run (existing ones come back as "already exists").
2. Create the pipeline by hand (Settings → Objects → Deals → Pipelines). Note the pipeline ID and every stage ID.
3. Import `hubspot-sync-lead`. Contacts upsert by email; deals upsert by the submission id (a unique property), so a resubmission updates instead of duplicating.
4. In the lead intake, call the sync **without waiting** (fire and forget), so a HubSpot outage never slows or fails the website form.
5. Never send an empty value: an empty string wipes what HubSpot holds.

### Module 2: Slack alerts + Claim
1. Slack app from a manifest: bot scopes `chat:write`, `users:read`, `users:read.email`; interactivity URL = the n8n claim webhook.
2. n8n "Slack - deal alerts": header-secret webhook → read deal + contact → Block Kit card (escape `&`, `<`, `>` in anything a visitor typed; deal names in `plain_text` headers).
3. n8n "Slack - claim button": verify Slack's signature on the **raw** body (`v0:timestamp:body`, HMAC-SHA256, 5-minute window, constant-time compare), with the signing secret in an n8n Crypto credential, never in the workflow. Map the Slack user's email to a HubSpot owner and set `hubspot_owner_id`.
4. HubSpot workflows: "new deal to Slack" (deal created in the pipeline → 1-minute delay → Send a webhook) and "stage changed to Slack" (stages the team cares about; turn on **Records can repeat runs**). Auth: API key from HubSpot's secret store, sent as a request header.

### Module 3: Calendly → HubSpot
1. The site's booking embed adds `utm_content=<lead id>` to the Calendly URL (a random id, never contact data). Calendly stores it on the booking.
2. n8n "Calendly - poll bookings" every 5 minutes: list events from 24 hours ago, **only the website's event type** (the API has no event-type filter, so filter in code), read invitees, compare with HubSpot meetings by a `calendly_invitee` property.
3. New booking → match the deal by lead id, accepted only if that deal's contact has the booking's email; otherwise the person's newest open deal → create a meeting, link it, move the deal to Call booked (only from New lead or Contacted), Slack card with the time.
4. Cancellation → meeting CANCELED (a reschedule is RESCHEDULED and leaves the deal), deal back to Contacted only from Call booked.
5. Save failed runs only (quiet runs every 5 minutes would fill the database).

### Module 4: Gmail drafts
1. Google Cloud: OAuth client (Web application, redirect = n8n's OAuth callback), consent screen **In production** (Testing tokens die after 7 days), Data access = `gmail.compose` only. Needs an app home page and privacy policy URL to publish.
2. n8n credential: Gmail OAuth2 with **Custom Scopes** = `gmail.compose` only (n8n's default includes full mailbox access).
3. n8n "Gmail - deal drafts": header-secret webhook with `?template=` → read deal, contact, meetings → skip rules (closed deal, other pipeline, stage moved on, no email, no consent, template already made) → build an RFC 2822 message (strict email check, CR/LF stripped, UTF-8 subject encoded) → `users.drafts.create` → note on the deal → append the template to a `drafts_made` checkbox property.
4. Three small HubSpot workflows, one per draft (simpler to read than branches): deal created → 1 minute → first reply; stage becomes Call booked → call prep; stage becomes Proposal sent → 3 days → nudge (n8n re-checks the stage).
5. Every template ends with the opt-out line the form's consent copy promises.

### Module 5: pipeline hygiene
1. Sweeper: search open deals, measure **time in current stage** (`hs_v2_date_entered_current_stage`), not "last activity" (the automation's own notes count as activity and would hide a stuck deal). One task per stale deal, never a second while the last is open, due end of day, assigned to the owner. One Slack digest, owners @-mentioned via `users.lookupByEmail`.
2. Snapshot: one sheet row per open deal, written RAW; skip if this week is already in the tab.
3. Set the workflow timezone to the client's, so the schedules mean their morning.

## 4. Security standard (every build must pass)

| Rule | How it's met |
|---|---|
| Every inbound webhook proves who's calling | HubSpot → n8n: secret header from HubSpot's secret store. Slack → n8n: signature check. Wrong secret = 403/401. Each webhook gets an entry in `security/probe.n8n.json` in the same commit |
| Secrets live in n8n credentials only | Never in a workflow field, a URL, the repo or a chat message. If one is pasted into a workflow by mistake, rotate it (the workflow's history keeps it) |
| Least privilege on every key | HubSpot service key: contacts, deals, owners (+ contacts/deals schemas for the setup run). Slack: the three bot scopes. Calendly: read-only. Gmail: `gmail.compose`. Remove anything unused |
| Visitor text is hostile until escaped | Sheets: RAW. Slack: escape `&<>`, plain_text headers. Discord: inline code, mentions off. Email: strict address check, no CR/LF in headers. HubSpot notes: HTML-escaped |
| Prove least privilege | E.g. with the Gmail credential, reading the inbox must return 403 |
| Hostile end-to-end test before handover | One real lead whose name is a spreadsheet formula, a markdown link, HTML and `@everyone`; check every destination shows it as plain text |
| Error alerts | Every workflow has the error workflow set; failures alert a private channel |
| Privacy | The privacy page lists every destination; consent copy matches the opt-out the emails offer |

Run the full loop with the `web-security-check` skill (repo scan, outside-in scan of the site and n8n, active probes) before launch and monthly.

## 5. Testing protocol

1. **Local code test:** run each Code node's logic with sample data (including non-ASCII names and hostile strings) before importing.
2. **Pinned tests in n8n (unpublished):** pin the trigger (and any read you need to fake, e.g. a deal in a given stage) and run. Each module needs: the happy path, every skip rule, a re-run that must not duplicate.
3. **Live test after publishing:** one real form submission with an `@example.com` address, through to every destination. Calendly blocks automated bookings, so the client clicks the booking themselves.
4. **Hostile test:** section 4.
5. **Clean up:** delete the test sheet rows; complete or delete test tasks; the client deletes test drafts in Gmail and cancels test bookings. Leave test deals only if the client wants sample data.

**Never press "Execute" on a published polling workflow.** A manual run in the same second as the scheduled one can create duplicates.

## 6. Go-live checklist

- [ ] All workflows published; no pinned data left (`pinData` empty).
- [ ] Every workflow's error workflow set; timezone set on scheduled ones.
- [ ] Credentials linked by ID (imports can auto-link a webhook to the wrong header credential: check).
- [ ] `security/probe.n8n.json` passes (wrong secrets refused on every webhook).
- [ ] Live test and hostile test passed, test data cleaned.
- [ ] HubSpot workflows published; delays at their real values (not the 1-minute test value).
- [ ] Client has the "how to switch it off" list (section 7).
- [ ] Docs updated: IDs, decisions, test log.

## 7. Running it (operations runbook)

**Daily (the client):** read the #leads cards, claim new leads, send or edit the Gmail drafts, complete sweeper tasks as deals move.

**Weekly:** glance at the Pipeline snapshot tab; it is the history the CRM doesn't keep.

**Monthly (you):** `web-security-check` scan of the site and n8n; keep n8n on the current release; check the error channel for anything recurring.

**When something looks wrong:**

| Symptom | First check |
|---|---|
| No Slack card for a new lead | n8n Executions: did "lead intake" and "sync lead" run? Then HubSpot workflow history for "new deal to Slack" |
| Booking not in HubSpot after 10 minutes | Was it booked on the website's event type? Was the poller published? Failed poller runs are saved; quiet ones aren't |
| Duplicate meeting | Someone ran the poller by hand. Delete the extra meeting (it goes to HubSpot's recycle bin) |
| No Gmail draft | The deal's `drafts_made` property already has that template, or a skip rule fired: the n8n execution's "Plan draft" output says which |
| Gmail drafts stopped everywhere | The OAuth token: is the Google consent screen still In production? Reconnect the n8n credential |
| Sweeper silent | Nothing was stale (it posts nothing then), or the deal's sweeper task is still open |
| HubSpot calls failing | Test accounts expire after 90 days without API calls; renew trials in the parent account |

**Switching parts off** (nothing else breaks): unpublish the HubSpot "… to Slack" workflows (alerts), the "… to Gmail draft" workflows (drafts), the Calendly poller (bookings), the sweeper or snapshot workflows. The lead intake and Sheets keep working regardless.

## 8. Handover pack

Give the client: this SOP's sections 1, 6 and 7; the list of credentials and where each lives (names only, never values); the privacy page wording; the security test report (`web-security-check` template); renewal dates (HubSpot test trials, any token expiry); and a short screen recording per module.

## 9. Gotchas learned on the reference build

- n8n's Code sandbox has no `URLSearchParams`; decode forms by hand.
- Slack's API answers HTTP 200 even on failure: check `ok`.
- HubSpot's workflow test box starts with the text "Test value", which is sent unless cleared.
- A new HubSpot property-change workflow runs each record once until "Records can repeat runs" is on.
- HubSpot can't clone an unpublished workflow; clone from a published one.
- HubSpot retries a webhook action for 3 days on 5xx/429, not on other 4xx. n8n should answer 200 on receipt; idempotency (the `drafts_made` property, the invitee property on meetings) makes retries harmless.
- Multiple-checkbox properties: values separated by `;`; a leading `;` appends instead of replacing.
- Calendly's embed must re-send the prefill on Calendly's first message: its app starts listening about 2 seconds after the iframe loads.
- Calendly's `/scheduled_events` has no event-type filter: filter in code, or other bookings leak into the CRM.
- Google: Testing-mode OAuth tokens expire after 7 days; publishing needs a home page and privacy policy URL; `gmail.compose` is a Restricted scope (100-user lifetime cap while unverified, fine for one mailbox).
- n8n imports can link a webhook to the wrong header credential: set credentials by ID after import.
- Editing a published n8n 2.x workflow creates a draft: press Publish again for the change to go live.
